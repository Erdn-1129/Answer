### 使用AI做了什么？

#### 1.地平线图该怎么理解？（gpt

我是从预估思考量最小的题目开始的，实际上的题目也就是二、三、四题，四题是我最不熟悉的，并且我选择的是设计方向，所以我从第四题开始，那么我最开始做的事是理解这个图形的整体实现的框架，我能理解x轴代表个体，y轴代表数值，然后是折线面积图。但是由于之前未接触过地平线图，所以未能理解为什么深色块必定包含在浅色色块，并且为什么是从y轴数值为0处开始。于是我将我的疑惑复述给chatgpt。

chatgpt给我解答，地平线图是固定y轴数值区间，将原本的折线图分割进行堆叠显示

#### 2.该使用什么技术栈？（gpt

> 我想用代码画一个三角形坐标系的地平线图，x轴是个体，y轴是某个数值。整个数据表有五个数值。意味着有五个三角形坐标系的地平线图组成一个360度的，长的像雷达图，但实际不是雷达图的图表，并且在其上方堆叠一个大小一致的雷达图来表现某个数值的均值。最终输出是html最好，我该用什么技术栈实现会省事好做

以上这段引用是我的prompt，chatgpt给我的回答是HTML+SVG+Javascript+D3.js

并且我询问了每个部分的作用是什么，HTML是页面框架，SVG是一种HTML元素用来画出，JS实现逻辑运算，D3.js则是js的一个工具集。

#### 3.vibe第四题（gpt+workbuddy

在询问使用什么技术栈后，我就开始着手要vibe了，在实际vibe之前我询问gpt具体的实现思路应该是怎么样的才能简洁，不用重复执行和修改。其实在有些使用gpt会顺着你的话说，导致跑偏，所以我同时使用workbuddy，把gpt输出的思路交给workbuddy，起到一个审查的作用，gpt执行，workbuddy审查，最后定下来这一版实现思路，然后开始执行。

在执行的过程中gpt很多时候会效果不佳，出现较大的问题，于是在输出效果跑偏了且修改prompt后依然跑偏，于是将项目交接给了workbuddy，确认了我要的预期效果，让workbuddy执行，最后呈现出我需要的效果后，让gpt进行代码审查，看是否有冗余和导致无法呈现效果的风险，在沙箱里跑测试。同样的审查流程又给workbuddy了一遍。
