# 设计思路

主要面向的是求职者。

一开始我想的是一个求职者到底卡在哪。捋下来就是六个问题，而且是有先后的。

我该进哪个行业、做什么岗位。我现在的学历和经验够不够格。同样是这个行业去哪个省更好。定了省去哪个城市。去了之后这个城市这个行业到底有哪些岗位、都要求什么。长远看我是该继续深造还是赶紧去攒经验。

这六个问题是一层套一层的，前面选完后面范围就小了。所以整套图就是顺着这条线走的，一张图只管一个问题，图跟图之间是往下钻的关系，不是六张各画各的。

## 能拿到的数据

| 字段        | 含义     |
| ----------- | -------- |
| JobId       | 岗位编号 |
| JobName     | 岗位名称 |
| Province    | 省份     |
| City        | 城市     |
| Education   | 学历要求 |
| Experience  | 经验要求 |
| Salary      | 薪资     |
| CompanyType | 企业类型 |

## 统一数据口径

原始薪资数据直接拿来比会出问题。

招聘网站上的月薪基本都是区间，不同岗位区间宽度差很多，直接拿上限比的话，那些写得特别宽的岗位就占便宜了，会被系统性高估。另一个是很多公司发十三薪十四薪，只看月薪会低估实际年收入，而求职者真正在意的其实是年收入。

所以做了两步归一化，就是这个公式。

```
真实月薪 = (月薪下限 + 月薪上限) × 13 ÷ 2 ÷ 12
```

前半段取区间中值，把大家拉到同一个标准上，去掉区间宽窄比较的影响。后半段把按十三个月发放折算成十二个月的口径，等于把年薪摊回每个月。

后面所有图里说的薪资都是这个真实月薪。这步要是搞错了，图画得再漂亮结论也是歪的。

## 整体链路

图一选行业和岗位，锁定行业之后进图二看学历和经验要求、判断自己够不够格，然后图三定去哪个省，省份定了图四定城市，城市定了图五看这个城市这个行业有哪些岗位、各要什么，最后图六回答我该深造还是攒经验。

---

## 图一 行业和岗位的散点花图

想回答的就是这么多个行业我该选哪个，光看岗位数量够不够。

横轴是真实年薪，纵轴是岗位数量。每一个花形图元是一个行业，它站在坐标系里的哪个位置，由这个行业的平均年薪和岗位总量决定。图元里面拆成扇形，每个扇形是一个岗位。扇形角度占比是这个岗位在该行业的招聘数量占比，半径是这个岗位在该行业的薪资水平，面积反映的是这个行业的岗位种类数量，种类越多花越饱满。外面套一圈白色虚线圆，代表这个行业的整体薪资水平，拿来当对比基准。

我最早打算用普通散点，一个点一个行业。但是后面觉得缺东西，散点只能表达一个行业的一个数值，可我想看的是行业之间怎么比、行业内部又是什么构成，这两件事必须叠在同一个画面里才有意义。人挑行业的时候，其实同时在挑这个行业里做哪个岗位。

内部结构怎么塞进去是第二个坎。用柱状图的话一个行业要占一大片地方，几十个行业根本放不下。扇形的好处是能在巴掌大的一块地方里同时说三件事，有多少种岗位、每种占多少、每种给多少钱。

白虚线圈是后加的。光有扇形半径的话，用户只能横向去比不同行业，判断不了这个岗位在本行业里到底算高还是算低。加一条行业平均基准，一眼就能看出某个岗位是高于还是低于整体水平，所以它代表的是相对大小而不是绝对值。

## 图二 行业的学历和经验要求分布

想回答的就是这个行业的门槛是什么，我适配吗。

左右两栏，左边学历要求分布，右边工作经验要求分布。柱子高度是这个条件下的招聘数量，柱子之间的高度差是不同要求档位之间的相对薪资差距。绿色标线标出该行业占比最大的学历和经验档位。

核心想法是让门槛和回报同时看得见。求职者看学历要求，关心的不只是招多少人，还有要求往上提一档工资能多多少。所以我让柱高身同时承担两个作用，既表示数量，又靠柱与柱之间的落差表示薪资差，理想效果是能直接看出要求越高薪资越高这个趋势到底成不成立。

绿线的作用是给个锚点，不然用户得自己在几个柱子里找最大值，太累。标出占比最大的那一档，用户就能立刻拿自己的条件去对照，看自己是不是正好落在主流档位上。

这张图我自己知道有个隐患，柱高同时表示数量和薪资差，严格讲是有歧义的，正式出图得在图例里讲清楚，或者把其中一个换成颜色。

## 图三 省份和行业的秩差矩阵

想回答的是同样是这个行业去哪个省，岗位多的省是不是也给钱多。

对每个省份乘行业的组合，分别给岗位数量和薪资水平算个秩，然后用薪资秩减掉岗位秩，得到秩差。正数是这个行业在这个省薪资占优，钱给得比它的岗位规模应得的更多。负数是岗位规模占优，招得多但薪资排位靠后。接近零说明薪资和岗位规模基本对得上。单元格明度表示平均薪资高低，越亮薪资越高。

这里最费劲的是怎么把两个量纲不同的东西放一块比。岗位数论个，薪资论元，直接做差或做比值都会被极端值带跑，比如某个省招了几万个岗位但薪资很低，那比值就没意义了。

所以后来改用秩，各自在自己那一列里排个名，只比相对位置不比绝对值。量纲问题没了，极端值的影响也被压住。秩差的意思就很直白，这个省的薪资排位比它的岗位规模排位高多少，多出来的那部分就是这个省给这个行业的溢价。

用矩阵而不是堆叠柱状图，是因为行业乘省份是个交叉结构，矩阵能让人横着竖着扫，找出整行偏亮或者整列偏暗的模式。

## 图四 城市薪资范围

想回答的是定了行业和省份之后，具体去哪个城市。

对该省份该行业该岗位，按城市展开。折线给出每个城市的最低薪资、平均薪资、最高薪资，柱状图给出每个城市的岗位需求数量。

到这一步用户已经知道要去哪个省了，剩下的就是城市之间的比较。而城市的比较说到底是收入和机会的权衡，一线城市薪资高岗位多但竞争也大，二线城市可能岗位少但性价比高。

所以我把薪资的上下波动和机会规模放进了同一个坐标系。只看平均值不行，两个城市平均薪资一样，一个最低八千最高两万，另一个最低一万二最高一万五，对求职者的意义完全不一样。给最低和最高，是让用户看到自己在那个城市里能摸到的上限和下限。

## 图五 行业和城市的散点雷达

想回答的是这个城市的这个行业具体有哪些岗位，每个岗位都要求什么。

横轴是城市，纵轴是岗位数量。每个岗位用一种颜色，形成不同颜色的散点。每个点不是圆点而是一个小雷达图，四个维度分别是学历要求、经验要求、薪资、薪资发放月数。

普通散点只能告诉我这个城市这类岗位有多少个，但求职者真正想知道的是这些岗位长什么样。所以我把雷达塞进了散点里，坐标负责说数量，雷达负责说画像。

四个维度里前三个是常识，第四个发放月数是我特意加的。原因跟前面那个薪资口径问题是一回事，一个月薪一万发十二个月，和一个月薪九千五发十四个月，实际到手是后者更多。只盯月薪会把这类岗位误判成低薪，把它单独留成雷达的一个维度，用户就能自己权衡。

## 图六 城市学历经验的薪资热力图

想回答的是我该继续深造还是先去工作攒经验。

矩阵形式，行是工作经验档位，列是学历档位，单元格颜色是这个城市这个学历这个经验组合对应的薪资水平。每个城市一个子矩阵，并排摆着。

前面五张图都是帮用户往外看，选行业选地方，这张图是帮用户往内看，评估自己该怎么投入。

深造还是攒经验，说到底就是学历乘经验两个离散变量的交叉组合比较。这种交叉结构最适合的就是热力图，看颜色就能比出往哪个方向走一步收益更大。比如某一行整体颜色很深，说明经验涨一档带来的薪资提升很明显。某一列整体很浅，说明再多读个学位在这个城市回报有限。

按城市分子矩阵，是因为这个结论因地制宜。同一个选择在一线城市和新一线城市的最优解可能完全相反，把城市分开摆，用户能直接对着自己目标城市那一块看。
